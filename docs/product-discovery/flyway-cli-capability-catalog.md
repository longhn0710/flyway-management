## Configuration inventory and policy

Flyway accepts legacy flat properties and modern TOML root / `environments.<name>` / `flyway` / plugin namespaces. CLI parameters override file settings. The [configuration index](https://documentation.red-gate.com/flyway/reference/configuration), [Flyway namespace](https://documentation.red-gate.com/flyway/reference/configuration/flyway-namespace), [environment namespace](https://documentation.red-gate.com/flyway/reference/configuration/environments-namespace) and [command-line usage](https://documentation.red-gate.com/flyway/reference/usage/command-line) are **current** documentation; they are not all proven usable in this pin. The appendix inventories all parameters printed by this pin's global and command help. The declaration evidence adds properties omitted from help, but is not an assertion that a Java getter is a public CLI key.

## Artifacts, repeatables and callbacks

Flyway supports more migration types than Manager: SQL, Java, script and baseline migrations; undo requires Teams. Manager normalizes SQL and bounded ZIP/TAR/TGZ packages into immutable V/R files, verifies hashes and freezes effective stream files per run. This transport can be reused across engines; SQL itself is not portable. An Oracle package cannot be automatically replayed on PostgreSQL. Each new target/stream needs its own qualified artifact.

Repeatables execute when checksums change; there is no Undo for them. Current repair eligibility rejects repeatable/superseded evidence to avoid unintended alignment. Preserve this constraint. [Callback events](https://documentation.red-gate.com/flyway/reference/callback-events) include inspection and validation events: an unrestricted `info` is not intrinsically side-effect-free. Callback filenames, uploaded executables and initialization SQL stay excluded.

## Machine-readable evidence and process contract

`-outputType=json` is printed by help. Actual [list-engines JSON](evidence/list-engines-json.txt) reports `version`, `command`, `edition`, and `dbInfoResults`; it does **not** enumerate tested server versions, despite broad wording in the command index. Native migration commands use command-specific schemas, not that metadata shape. Retain `operation`, `flywayVersion`, database identity, warnings, exit status and raw bounded stdout/stderr along with the semantic result. Info includes native state/category, filepath, installer, timing and timestamps; Validate returns validation status/invalid migrations; Migrate records executed migrations; Repair records removed/aligned/deleted entries. Existing [Info acceptance](../projects-flyway-info-acceptance.md) and parser tests are evidence for this application's current paths, not for all commands above.

No new database-backed JSON was generated in Phase 6. Do not infer success from exit zero alone, silently replace malformed results with empty history, discard unknown state labels, or coerce the metadata JSON into an execution result. Native command errors and failed captures remain evidence. Never put passwords in argv or debug logs. A future API-only operation still requires the same authorization, immutable plan, command allowlist and audit as UI execution.

## Runtime and JDBC requirements

Use the complete approved 13.10.3 distribution and its bundled **Eclipse Adoptium JRE 25.0.4+7-LTS, Linux x86_64**, observed in the verified [JRE release metadata](evidence/java-runtime.txt). Version, full manifest and private invocation are rechecked before execution. JDBC modules and drivers are separate dependencies: a loaded engine label can exist without a usable driver. Priority driver versions and other missing dependencies are catalogued in the [database matrix](flyway-database-support-matrix.md). No jar hot-loading or arbitrary `jarDirs` is proposed. [Pinned components](evidence/runtime-components.txt) include both Community and proprietary jars, community plugin filenames `10.25.15`, and a compare plugin; `-v` reports some plugin versions `10.25.14`. Record both rather than rewriting the approved pin.

Mongo JavaScript needs external `mongosh`; SQLFluff needs an external installation; advanced comparisons/build environments may need additional binaries or credentials. Native-connector implementations have different transaction/output limitations and are not interchangeable with the accepted Oracle JDBC path. Documentation or future releases may expand these surfaces; this package approves no newer runtime behavior.

### Release chronology and newer-version claims

The [official release notes](https://documentation.red-gate.com/flyway/release-notes-and-older-versions/release-notes-for-flyway-engine), accessed 2026-10-17 and last updated October 15, have **13.10.2** as their newest visible release heading, behind the actual verified **13.10.3** binary. No post-13.10.3 release capability was established. Do not invent a newer-version feature list or infer 13.10.3 changes from that documentation gap. The pin remains the authority for shipped command/help/dependency availability.

The notes explicitly place per-environment plugin settings in 13.10.0, named stdin connection testing in 13.8.0, Snowflake Postgres recognition in 13.6.0 and changed JSON timestamp offsets in 13.2.0. These predate the pin, but remain separate from licensed/accepted Manager coverage. “Coming soon” items in the feature summary, previews and unbundled community adapters stay uncommitted; future upgrades need another pin-specific assessment.
