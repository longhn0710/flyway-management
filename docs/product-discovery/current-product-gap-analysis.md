## Constraints to carry forward

1. Current stream configuration includes host/port/service/transport/environment/schema/history/config plus runtime pin. New engine/database/auth/TLS identity must join new fingerprints; existing Oracle fingerprints cannot change silently.
2. `database_targets` has `UNIQUE(host,port,service)` and service is nonempty. `target_schemas` and account names use `COLLATE NOCASE`; Go Oracle identifiers are uppercased. These are structural issues, not UI-label fixes.
3. `history_schema != schema.name` is blocked as NOT_VERIFIED. Do not broaden it while adding an engine. Runtime sets `defaultSchema` to the history schema, so generalizing separate history would also affect execution namespace.
4. `schemas` and allowlists restrict Manager choices, not statements. A privileged account can reference another schema/catalog explicitly. New adapter privilege classifications must say potential/unknown/unsupported, never “all migrations guaranteed safe”.
5. Credentials are account-bound ciphertext; retained history has a documented readable-run identity policy. Viewers must not fetch admin execution-account catalogs. Keep literal credential escaping, unsupported control-character rejection and private config permissions.
6. Artifact-relative Info, malformed-output failures, queued dependencies, held streams, no implicit SQL retry and ambiguous timeout/restart handling are product guarantees. Transactional engine support does not justify relaxing ambiguity handling.
7. Catalog/project enumeration currently scans authorized registry/run records and the frontend paginates existing APIs. Acceptable at current scale; new global indexing, distributed workers and scheduler infrastructure need measured demand.

These are existing boundaries or identified changes, not fresh penetration-test findings. Full build/browser/security success is recorded in prior acceptance; Phase 6 does not claim a new application test run or a fresh live environment certification.
