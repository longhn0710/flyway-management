## Implemented behavior

SQLite migration 008 adds an immutable engine discriminator, explicit PostgreSQL database, profile revision, engine-qualified endpoint uniqueness and a password/verify-full trust profile. It follows the dedicated-connection, transactional parent-table rebuild and foreign-key validation/restoration used by migration 007. Unexpected custom target indexes/triggers and invalid references fail closed. There is no downgrade migration; older binaries reject v8. A coordinated compatible-binary/backup restore is required for rollback.

Legacy Oracle input defaults to Oracle in memory. Its stored rows, snapshot JSON, configuration tuple and fingerprints are preserved. Oracle-only URL/config generation and the existing narrow repair branch retain their original behavior. New PostgreSQL snapshots use version 2 and include engine, database, endpoint/environment, schema/history, authentication policy, CA content hash/revision and runtime configuration. Certificate contents, passwords and private temporary paths do not enter semantic snapshots. Cosmetic edits preserve profile identity; credential rotation preserves history. A concurrent change to implicitly reused credentials or trust rejects Save. A connection with streams or other accounts cannot silently change destination or trust.

The PostgreSQL adapter uses a reproducibly compiled Java 11 helper and the manifest-pinned JDBC jar. Credentials use bounded stdin transport; trust is staged privately. Fixed read-only metadata queries verify actual database, session/effective role and PostgreSQL major before discovery or CLI dispatch. They list existing non-system schemas with USAGE, report actual ownership and classify CREATE as **potential**, not proof that arbitrary DDL will succeed. No schema creation, privilege grant, arbitrary query API, raw JDBC URL, driver class or free-form properties were added. The accepted identifiers are lowercase, unquoted database/schema/role/history names up to 63 bytes, including leading underscore.

Administrative registration re-probes and atomically saves target, encrypted credential, selected schema references, account-specific allowlist and explicit user grants. Empty-password edits preserve ciphertext/version; explicit rotation increments credential version. Readonly accounts may inspect an explicitly selected schema after uncertainty acknowledgment. All existing operate/PROD, activity, mapping, artifact checksum, held/busy stream and pinned-runtime safeguards apply to refresh. The dispatched command is the literal `info`; callbacks, implicit baseline, schema creation, placeholders and Clean remain disabled. PostgreSQL Repair is rejected at the runtime boundary.

The existing frontend now supports PostgreSQL fields, CA input, Test Connection, discovery/allowlist selection, saved-account editing, database-qualified instance/history/Info details and truthful migration-disabled states. Oracle remains Operational; other engines remain unavailable. The server-owned `/engine-capabilities` endpoint distinguishes implemented inspection from migration policy. Recorded Info remains historical and artifact-relative; profile/destination/environment/history drift is visible.

## Remaining acceptance and delivery boundary

The PostgreSQL migration server gate is enforced before preflight/submission and again for queued plans. The UI offers no working migration action for PostgreSQL. Enabling it requires a separate controlled Manager worker/product acceptance increment covering transactional and partial failures, nontransactional rejection, scoped service tokens and PROD, duplicate API submissions, independent schema/database streams, concurrent reservations, changed frozen profiles/credentials, revocation, predecessor failure, malformed/truncated output, timeout/restart/process termination, held failures and evidence-preserving operator recovery. The prepared native fixture suite is an executable starting point, not proof of those Manager behaviors. No generic Repair or manual SQLite/history edits are a recovery plan.

Qualification is restricted to the tested local PostgreSQL 17.11 password/SCRAM/verify-full profile, existing lowercase schemas and same-schema history. No other PostgreSQL major, managed service, certificate-client authentication, quoted identifiers, nontransactional migration policy or additional engine is accepted. Production/deployed acceptance was **not performed**. This package is ready for local source review with migration disabled. Local branch `feat/postgresql-foundation` contains focused backend (`23b0ff3`) and frontend (`b0ee6a8`) commits plus the acceptance/harness package. No remote PR was created because that would require publishing the unpushed branch; push, publication, CI promotion and deployment remain separate authorization boundaries.
