# Flyway runtime adapter

`Runtime` invokes only `info`, `validate`, `migrate`, and `repair`. It creates a mode-0700 workspace and mode-0600 configuration/snapshot files, passes the password in configuration rather than argv, clears the inherited environment, caps Java heap at 512 MiB, bounds output, caps timeout at one hour, and redacts passwords from plain and structured results. On Unix timeout cancellation kills the subprocess group. Migration and repair failures with unverified outcomes are marked ambiguous because Oracle DDL can commit before Flyway exits. Generated config disables clean, schema creation, baseline-on-migrate, out-of-order, placeholders, SQL*Plus, and callbacks; it enables migration naming validation and validate-on-migrate and permits only pending migrations during pre-migration validation (`*:pending`); future/missing/changed/failed validation remains strict.

`Config.SHA256` is the SHA-256 of the exact bytes of `flyway-manifest.sha256` in the executable's distribution directory. The manifest format is one line per regular distribution file, `<lowercase SHA-256><two spaces><relative path>`. The manifest itself is excluded; every other regular file must appear exactly once, and symlinks, unlisted files, missing files, and digest mismatches fail closed. The manifest digest must be delivered through a trusted configuration channel. Merely calculating this digest from the files at startup is not a trust anchor. `Check` also requires a manifest-covered `ojdbc*.jar` and `flyway-database-oracle*.jar`, checks Java availability, and revalidates the exact CLI version before every command. `Install` accepts only an operator-supplied source directory, copies a bounded complete distribution to a private staging directory, verifies it, and atomically publishes to a version-and-pin path without replacement. It does not download or bundle a runtime. The caller must establish that acquisition, licensing entitlement, and release-manifest provenance are approved before invoking installation; this package cannot independently verify licensing rights.

Readiness confirms only the local distribution, version, and Java executable presence. It never contacts Oracle and never claims network, authentication, target identity, schema, history table, or privilege verification. Oracle connectivity was not exercised in tests.

## Flyway and Oracle compatibility findings

Findings below are based on Redgate's official documentation, accessed 2026-10-16:

- The Flyway CLI supports `-outputType=json`; documented `migrate` output includes `migrations`, `migrationsExecuted`, `flywayVersion`, and `operation`; `validate` includes `invalidMigrations`, `validationSuccessful`, `validateCount`, and `operation`; `repair` includes `repairActions`, `migrationsRemoved`, `migrationsDeleted`, `migrationsAligned`, and `operation`. Success requires exit code zero, exact pinned version, matching operation, and command-specific fields. Failed but parseable JSON remains available to the caller for safety decisions. [Output type](https://documentation.red-gate.com/flyway/reference/command-line-parameters/output-type-parameter), [migrate](https://documentation.red-gate.com/flyway/reference/commands/migrate), [validate](https://documentation.red-gate.com/flyway/reference/commands/validate), [repair](https://documentation.red-gate.com/flyway/reference/commands/repair), [info](https://documentation.red-gate.com/flyway/reference/commands/info).
- Redgate documents `jdbc:oracle:thin:@//host:port/service`, Oracle JDBC support, and Oracle 19c/21c support. Current docs say the Oracle driver ships with the Flyway CLI. That availability is distribution/version-specific and the complete manifest check verifies whatever files the trusted distribution contains; this project has not verified a real Oracle connection. [Oracle driver reference](https://documentation.red-gate.com/flyway/reference/database-driver-reference/oracle-database), [supported databases](https://documentation.red-gate.com/flyway/getting-started-with-flyway/system-requirements/supported-databases-and-versions).
- Standard SQL and PL/SQL blocks delimited by `/` are documented. Oracle SQL*Plus commands such as `@`, `@@`, `WHENEVER`, and `SPOOL` are documented as Flyway Teams SQL*Plus support; they are not assumed compatible with Community. This adapter disables `oracle.sqlplus` and does no SQL rewriting. [Oracle driver reference](https://documentation.red-gate.com/flyway/reference/database-driver-reference/oracle-database).
- `repair` removes failed migration entries, aligns checksums/descriptions/types, and marks missing migrations deleted. Redgate requires the same locations used for migrate. The adapter executes repair only when explicitly requested and supplies the passed snapshot locations; policy for automatic eligibility and unrelated history safety belongs to the orchestration layer. [repair](https://documentation.red-gate.com/flyway/reference/commands/repair), [info](https://documentation.red-gate.com/flyway/reference/commands/info).
- `info` JSON includes `schemaVersion`, `migrations`, `flywayVersion`, and `operation`; the adapter preserves this payload for history inspection. Flyway documents that setting `defaultSchema` changes Oracle current schema to that value, which can affect remote links when it differs from the logged-in user. `schemas` names managed schemas. Actual Oracle cross-schema privileges and database behavior remain live-acceptance items. No claims are made about Oracle implicit commits or repair rollback; repair does not undo user DDL.

No Flyway binary is bundled or downloaded by this package. No license is bypassed. Distribution pinning and actual 19c/21c compatibility require an approved, pinned Flyway distribution and separately authorized disposable Oracle labs.

The info adapter accepts documented `filepath` and `installedOnUTC` fields and normalizes temporary location prefixes only for evidence comparison; it preserves raw JSON. Explicit pending-migration allowance is necessary before migrate; it does not excuse checksum/type/name changes or missing/future/failed history. The exact chosen CLI/Java/JDBC combination still requires live acceptance.
